# 第一阶段可执行规格

## 1. 项目范围

预编码加速器执行一次复数矩阵向量乘法：

```text
x[i] = sum(W[i][j] * s[j]), j = 0..K-1
```

第一阶段固定配置为 `Nt = 4` 根发送天线、`K = 4` 个用户或数据层。后续 RTL 可以扩展到 8x8，但第一版黄金行为以 4x4 为准。

ZF/MMSE 预编码矩阵的生成不属于当前 DUT 的职责，矩阵 `W` 由软件模型提供。

## 2. 复数运算规则

对于 `(a + jb) * (c + jd)`：

```text
real = a*c - b*d
imag = a*d + b*c
```

位精确参考模型中的所有运算都使用整数中间值，不允许在位精确计算路径中隐藏使用浮点运算。

## 3. 定点格式

| 数据 | 位宽 | 小数位数 | 整数解释方式 |
|---|---:|---:|---|
| 符号实部/虚部 | 16 | 14 | 有符号二进制补码 |
| 矩阵系数实部/虚部 | 16 | 14 | 有符号二进制补码 |
| 标量乘积 | 32 | 28 | 保留完整精度的有符号乘积 |
| 复数乘积 | 33 | 28 | 两个乘积相加或相减 |
| 累加器实部/虚部 | 40 | 28 | 有符号数，每次 MAC 后检查范围 |
| 输出实部/虚部 | 16 | 14 | 舍入并饱和后的有符号数 |

对于任意具有 `F` 个小数位的存储整数 `q`：

```text
real_value = q / 2**F
```

16 位 Q14 格式可以表示的范围为 `[-2.0, 1.99993896484375]`。

## 4. 量化规则

浮点输入值先乘以 `2**14`，再舍入到最近整数；当数值恰好位于两个整数中间时，向远离零的方向舍入。最后将结果饱和到 16 位有符号整数范围。

NaN 和无穷大不属于合法的模型输入。

输出累加器包含 28 个小数位。输出时使用有符号最近值舍入将其缩减为 14 个小数位，半值仍向远离零的方向舍入，之后饱和到 16 位有符号数。输出不允许发生回绕（wraparound）。

## 5. 累加器规则

每个复数乘积都保留完整精度。乘积严格按照矩阵列顺序 `j = 0, 1, 2, 3` 进行累加。

每次加法完成后都执行一次 40 位有符号范围检查。如果发生溢出，模型抛出 `FixedPointOverflow`，不得静默回绕或饱和。对于合法的 4x4、16 位输入，40 位累加器具有足够的保护位余量。

## 6. 数据布局

Python 模型使用形状为 `(4, 4)` 的数组表示矩阵 `W`，使用形状为 `(4,)` 的数组表示符号向量 `s`。

矩阵的行对应输出天线，列对应用户或数据层。浮点模型使用 NumPy 复数表示数据；位精确模型使用 `ComplexInt` 整数对分别保存实部和虚部。

序列化测试向量分别保存实部和虚部的有符号整数。测试向量还包含 16 位二进制补码的十六进制表示，可直接提供给 RTL testbench 使用。

## 7. 结果比较规则

- RTL 正确性：RTL 输出必须与位精确模型的有符号整数输出完全相等；
- 数值质量：将定点输出反量化后，与浮点模型输出进行比较；
- EVM 计算公式：`sqrt(sum(abs(error)^2) / sum(abs(reference)^2))`；
- 当参考信号能量为零时，只有误差也为零，EVM 才定义为 0，否则定义为无穷大。

## 8. 第一阶段验收标准

- 浮点模型和定点模型通过确定性单元测试；
- 覆盖边界舍入、正向饱和和负向饱和；
- 覆盖复数乘法以及 4x4 MAC 累加顺序；
- 至少 10,000 组带固定随机种子的 4x4 用例通过模型不变量检查；
- 使用相同随机种子时，生成的测试向量完全一致；
- 输出同时包含有符号整数和可供 RTL 使用的十六进制字段。

## 9. 后续 RTL 接口约定

第一版 RTL 核心将使用 `valid/ready` 流式接口。只有在 `valid && ready` 成立时才发生一次数据传输；发生阻塞时，数据和附带控制信息必须保持稳定。

复位将取消正在处理的输入向量，并清除输出有效信号。AXI-Stream、AXI-Lite、8x8 模式、矩阵双缓冲、矩阵版本跟踪和 UVM 验证环境将在后续阶段实现。
