# new第10阶段：最坏定点数值场景搜索与EVM分析

## 阶段目标

本阶段回答两个问题：

1. 当前16位Q1.14格式在正常通信输入下是否合理；
2. 哪些输入最容易造成输出饱和、最大EVM和最大累加器幅值。

`model/numeric_analysis.py`使用NumPy批量执行与RTL一致的复数Q14乘法、40位Q28累加、半值远离零舍入和16位饱和。浮点路径、量化输入路径和最终定点输出分别保留，因此可以区分：

- 输入量化误差；
- 舍入与输出饱和造成的实现误差；
- 两者叠加后的端到端EVM。

## 搜索方法

正式搜索固定种子为`20260808`，共分析120000组4x4矩阵向量：

- 25000组归一化QPSK；
- 25000组归一化16QAM；
- 25000组归一化64QAM；
- 25000组全16位范围均匀随机压力输入；
- 20000组围绕当前最坏样例继续变异的反馈搜索。

归一化场景将预编码矩阵Frobenius范数设为0.9，QAM符号采用单位平均功率。压力场景故意取消功率约束，用于寻找硬件边界，不代表正常无线链路的信号分布。

运行命令为一行：

```powershell
python -m scripts.search_numeric_worst_cases --samples 100000 --mutation-samples 20000 --batch-size 2000 --seed 20260808 --output-dir reports/generated/stage10
```

生成文件：

```text
reports/generated/stage10/stage10_numeric_search.json
reports/generated/stage10/stage10_numeric_search.md
```

反馈搜索找到的最大累加器绝对值为：

```text
8,586,625,807
```

40位有符号累加器正向上限为`549,755,813,887`，该样例仅使用1.561898%。这说明40位累加器对当前4x4数据通路具有充分保护位，也为未来8x8扩展保留了余量。

## Q1.14结论

Q1.14对当前设计是合理的，但必须附带系统约束：预编码矩阵需要做功率归一化，输入符号采用标准单位平均功率星座，并保证期望输出分量主要落在`[-2, 2)`。

Q1.14不适合“矩阵和符号每个实虚分量都可以独立达到满幅且无需缩放”的接口定义。该情况下4项复数乘积可能相干叠加，输出远超Q1.14范围；本次全幅压力搜索中99.804%的用例发生至少一次饱和。若系统无法保证归一化，应增加可配置缩放、块指数或更宽输出，而不是修改位精确模型掩盖饱和。

## RTL固化回归

反馈搜索得到的最终峰值累加器样例已固化为UVM测试`precoder_numeric_worst_test`。它同时包含3个饱和输出和1个未饱和输出，逐拍检查输出实部、虚部、饱和标志和版本。

服务器运行命令：

```bash
UVM_TEST=precoder_numeric_worst_test SEED=20260808 VECTORS=1 RUN_LOG=build/vcs/uvm/stage10_numeric_worst.log bash sim/run_uvm.sh
```

VCS结果为4路输出全部位精确匹配，`UVM_ERROR=0`、`UVM_FATAL=0`、SVA failure为0。
