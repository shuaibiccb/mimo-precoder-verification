# new第11阶段：性能预测模型与性能计数器闭环验证

## 阶段目标

本阶段验证性能计数器不是“寄存器能够读出非零值”这么简单，而是建立一套独立的 UVM 周期模型，逐周期预测计数器值，并把预测值与 RTL 内部计数器及 AXI-Lite 软件可见读数进行闭环比较。同时对单向量延迟和连续向量吞吐率建立可重复的性能基线。

## 验证结构

`tb/uvm/performance_if.sv` 将以下事件和计数器送入 `precoder_performance_monitor`：

| 项目 | RTL 计数条件 |
|---|---|
| `cycle_count` | 清零后的每个有效时钟周期 |
| `input_vector_count` | 第 4 个输入拍完成握手，即完整输入向量被接收 |
| `output_vector_count` | 第 4 个输出拍完成握手，即完整输出向量被接收 |
| `input_stall_count` | `s_axis_tvalid && !s_axis_tready` |
| `output_stall_count` | `m_axis_tvalid && !m_axis_tready` |
| `saturation_count` | 每个发生饱和的输出拍 |
| `cfg_write_count` | 一次合法矩阵系数写入 |
| `commit_count` | 一次合法 Bank commit 请求 |

monitor 独立累计这 8 项事件，并在每个周期与 RTL 计数器逐项比较。测试随后通过 AXI-Lite 地址 `0x20` 到 `0x3c` 读回 8 个计数器；monitor 在 AR 握手周期保存该时刻的期望值，在 R 握手时检查返回数据，因而不会把读响应等待期间新增的周期错误地计入期望读数。

## 延迟预测规则

延迟从完整输入向量被 DUT 接收的周期开始，到完整输出向量完成握手的周期结束。当前 4x4、4 路并行 MAC 微架构的实测规则为：

```text
单向量实际延迟 = 9 个固定周期 + 该向量输出阶段的反压周期数
```

无反压时，所有向量的延迟均为 9 周期。输出 `valid && !ready` 每持续一个周期，完成时间相应增加一个周期。UVM monitor 对每个向量分别记录接收周期、输出反压周期和完成周期，预测值与实际值不一致即报 `UVM_ERROR`。

这里的 9 周期是单事务延迟，不等于连续事务启动间隔。当前核心一次只处理一个向量，连续向量在输入、计算和输出阶段之间不能完全流水重叠；因此理想配置下相邻完整输出向量间隔为 16 周期，在 100 MHz 时钟下的理想持续吞吐率为：

```text
100,000,000 / 16 = 6,250,000 向量/秒
```

## 定向场景

`precoder_performance_test` 在计数器清零后制造并检查：

- 1 次矩阵配置写和 2 次 Bank commit；
- 连续输入导致的输入阻塞；
- 无反压、随机反压、混合反压和 8 周期长阻塞；
- 每个向量 4 个饱和输出，用于核对饱和计数；
- 8 个计数器的周期镜像值和 AXI-Lite 读回值；
- 每个向量的预测延迟、平均延迟和持续吞吐率。

## 正式回归结果

服务器 VCS 回归命令：

```bash
RUNS=20 VECTORS=12 BASE_SEED=20260808 bash sim/run_performance_regression.sh
```

20 个 seed 共检查 240 个向量，`UVM_ERROR=0`、`UVM_FATAL=0`、计数器不一致为 0、延迟预测不一致为 0。四种配置各运行 5 个 seed，结果如下：

| 配置 | 输出反压设置 | 平均延迟 | 延迟范围 | 100 MHz 平均吞吐率 |
|---|---|---:|---:|---:|
| `ideal` | 无 | 9.000 周期 | 9～9 | 6,250,000 向量/秒 |
| `random20` | 20% 随机 | 9.867 周期 | 9～14 | 5,927,592.816 向量/秒 |
| `mixed` | 35% 随机并每 3 周期阻塞 | 14.333 周期 | 11～23 | 4,690,905.487 向量/秒 |
| `long_burst` | 10% 随机并在输出开始时阻塞 8 周期 | 17.517 周期 | 17～19 | 4,080,177.136 向量/秒 |

逐 seed 原始结果保存在：

```text
build/vcs/uvm/performance/summary.csv
```

## 完成判据

只有同时满足以下条件，本阶段才算通过：

1. 20 个性能回归 seed 全部完成，240 个向量全部输出；
2. 8 个硬件计数器与 UVM 周期模型逐周期一致；
3. 8 个 AXI-Lite 计数器读回值与请求时刻的模型值一致；
4. 每个向量满足 `9 + 输出反压周期数` 的延迟预测；
5. 理想配置延迟固定为 9 周期，持续吞吐率为 625 万向量/秒；
6. `UVM_ERROR` 和 `UVM_FATAL` 均为 0。

上述判据已全部满足。该基线也给出了后续性能优化的方向：若要提高理想吞吐率，需要让输入、计算和输出阶段重叠或引入多事务流水，而不是只提高 AXI 接口的 `ready` 比例。
